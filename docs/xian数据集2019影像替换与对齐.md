# Xi'an 数据集 2019 影像替换与对齐

> 2026-07-05。把 didi/xian 数据集的卫星影像从 Google-2024 换成 Esri Wayback 2019,让 sat 与 rn/traj 标签(2019)时间对齐。本文记录数据情况、对齐原理、跨项目替换范围与验证结论。

---

## 一、为什么要换

didi/xian 数据集的标签都是 **2019**:
- rn(路网 GT):`osm/xian-plus-190101.osm.pbf`(2019-01-01 OSM 抽取)
- traj(轨迹):`rn-comp-xa-190101-seg5`(2019 快递员 GPS)
- active:`rn-comp-xa-190101-didi`

但卫星影像 `DelvMap/rawdata/sat_img.png` 是 **Google 2024** 的高分影像。sat(2024)与 rn/traj(2019)差 5 年,路网、建筑、地物变化大,导致:
- 训练时模型看到的路与 GT 不一致(尤其新建/改建路段)。
- 评测时 sat 上的路与 GT 路网错位,IoU/F1 虚低。
- traj 轨迹点落在 2024 影像上,与 2019 路网对不上。

**目标**:拉一张同区域、同 bbox、同画布尺寸的 **2019** 遥感影像,替换掉 2024,使 sat 与标签同年代。

---

## 二、2019 影像数据情况

### 来源:Esri Wayback

Esri Wayback(`livingatlas.arcgis.com/wayback`)是 World Imagery basemap 的历史版本归档,每个版本是一个 release(全局快照层)。

- **release = 645** = 2019-06-26 vintage(Wayback app `active=645` → MapServer release 层号 → tile URL `{release}`)。
- 映射验证:Porto 用 `active=31144`(=release 31144,2014-06-11)成功拉过,证明 `active=` == tile URL release 号。
- 瓦片 URL:`https://wayback.maptiles.arcgis.com/arcgis/rest/services/World_Imagery/MapServer/tile/645/{zoom}/{y}/{x}`

### 关键参数(与原 2024 sat_img.png 完全一致)

| 项 | 值 |
|---|---|
| bbox | lat `[34.206385, 34.279658]` × lon `[108.917423, 108.99286]`(西安城区,与 `config/xian.json` 一致) |
| 画布尺寸 | **5625 (W) × 6610 (H)** 像素(PIL size `(5625,6610)`,numpy shape `(6610,5625,3)`) |
| 分辨率 | ~1.493 m/px Web Mercator(x=1.4929, y=1.4928,均匀→确认 W/H 方向正确) |
| 投影 | Web Mercator (EPSG:3857) |
| 模式 | RGB(原 2024 是 RGBA,但消费者用 `cv2.imread(IMREAD_COLOR)` 读,丢 alpha,故 RGB 即 drop-in) |

产物:`sam_road/tools/prepare_dataset/xian_2019_wayback_645.png`(81 MB)。

### 下载流程

用 `tools/prepare_dataset/esri_wayback.py` 的 `fetch_wayback_canvas()`:
1. `GetMapInRect(zoom=17, release=645)` 拉 z17 瓦片(957 个,29×33 网格)拼接成原生 Mercator 裁剪 **7031×8262**。
2. `cv2.resize(LANCZOS4)` 缩放到 **5625×6610**(下采样因子 ~0.80)。
3. 存 RGB PNG。

调用脚本:`tools/prepare_dataset/xian_rsimg_test.py`(设定 xian 参数 → 调库 → 出图)。

> **网络注意**:arcgis 域名在国内常被 DNS 污染(wayback 解析到 Facebook IP)。`esri_wayback.py` 已加固:`requests` + 浏览器 UA + 超时 + 有限重试 + 并行 + 不中断。若仍 SSL EOF,用 `HTTPS_PROXY=http://127.0.0.1:7897 python xian_rsimg_test.py` 走 Clash 代理(requests 自动读环境变量,代码不用改)。

## 三、对齐原理

### 为什么纯 resize 就对齐(无需 warp 重投影)

`GetMapInRect` 的裁剪是纯 Web Mercator:
- `lonlat2TilePos` 用与 `wgs84_to_mercator` 相同的 `log(tan(...))` 公式。
- 裁剪 `img[y1:y2, x1:x2]` 取 NW 角 `(min_lon, max_lat)` 到 SE 角 `(max_lon, min_lat)` 的瓦片像素偏移。

因此原生裁剪(7031×8262)**恰好覆盖 bbox 的 Mercator 范围**,与原 2024 `sat_img.png` 同投影、同范围。两者唯一差异是像素分辨率/数量,故纯 `cv2.resize` 即地理对齐,无需 `cv2.warp`。

### 长宽比验证(对齐的数值保证)

| | 宽高比 |
|---|---|
| z17 原生裁剪 7031×8262 | 0.8510 |
| 目标 5625×6610 | 0.8510 |
| bbox Mercator ext_x/ext_y | 0.8511 |

三者一致 → resize 各向同性(0.009% 偏差来自 `int()` 截断,亚像素级,可忽略)。

### 切片生成(400×400 region)

samroad 的 `region_{c}_sat.png`(400×400)由 `download_use_osm.py --sat_source local:<2019sat>` 生成:
- `get_local_sat()`(`download_use_osm.py:143-163`)把每个 region 的 lat/lon bbox 经 Mercator 重投影,从大图采样 400×400。
- 与原 2024 切片**同公式同 bbox**,故 region 编号、坐标、黑边完全一致,只是影像内容从 2024 变 2019。

### DelvMap 切片生成(256×256 src_split)

DelvMap 的 `dataset/didi_xian_train/src_split/{n}.png`(256×256)由 `prepare_didi_trainset.py` 生成:
- 从 `rawdata/sat_img.png` 用 `get_local()`(同 `get_local_sat` 公式)采样 400×400 region。
- 再 sliding 2×2 crop 成 4 个 256×256(offsets `[0,144]×[0,144]`,stride 144,overlap 112)。
- `patch_idx = region_idx * 4 + off`,off `0=TL, 1=TR, 2=BL, 3=BR`。

## 四、跨项目替换范围

所有 sat 切片都源自同一张 5625×6610 大图(经 Mercator 重投影),共 **4 处切片 + 1 张大图**:

| # | 位置 | 数量 | 尺寸 | 生成方式 |
|---|---|---|---|---|
| 1 | `sam_road/datasets/didi/xian/2019_400/region_{c}_sat.png` | 378 | 400×400 | `download_use_osm.py` 重新生成(源头) |
| 2 | `P2CNet/data/didi/xian/2019_400/region_{c}_sat.png` | 378 | 400×400 | copy samroad(字节同源) |
| 3 | `DelvMap/datasets/didi/xian/2019_400/region_{c}_sat.png` | 378 | 400×400 | copy samroad(评测脚本用) |
| 4 | `DelvMap/dataset/didi_xian_train/src_split/{n}.png` | 1512 | 256×256 | 替换 sat_img.png + 重跑 `prepare_didi_trainset.py` |
| 5 | `DelvMap/rawdata/sat_img.png` | 1 | 5625×6610 | 直接替换为 2019 版 |

**P2CNet / DelvMap-didi 与 samroad 字节同源**(md5 验证),故 #2、#3 直接 copy,#1 改完它们跟着 copy 即可。

### 不在替换范围(已确认)

- `DelvMap/dataset/xian_2019_delvmap/basemap_split/`(灰度,旧管线,有泄漏问题,已弃用)
- `P2CNet/saved/didi_xian/.../sat_maps.png`(模型推理可视化产物)
- `sam_road/docs/imgs/xian_sat_gtgraph_align/`(文档配图)
- 所有 mask / label / traj 文件(`processed/`、`region_*_traj.png`、`region_*_gt.png` 等)
- GT 图结构(`graph_gt.pickle`、`refine_gt_graph.p`)

## 五、验证结论

替换后 6 项验证全部通过:

| 检查 | 结果 |
|---|---|
| 尺寸/模式 | region sat 400×400 RGB、src_split 256×256 RGB、sat_img 5625×6610 RGB ✓ |
| 内容变 2019 | region_0 均值 `[66,72,67]`(原 2024 `[92,93,95]`)✓ |
| 跨项目同源 | P2CNet、DelvMap-didi 与 samroad md5 一致 ✓ |
| DelvMap src_split 对齐 | region_0 四角(TL/TR/BL/BR)与 samroad region sat 像素差 = **0.00** ✓ |
| DelvMap 对齐检查 | `prepare_didi_trainset.py --verify` 像素差 = **0.05**(应 <3)✓ |
| GT 完整性 | `graph_gt` region_0 = 193 节点/187 边,与归档旧版结构一致(内容未变)✓ |

### GT 漂移说明

`download_use_osm.py` 重跑会重算 GT(`graph_gt.pickle`、`refine_gt_graph.p`、`gt.png`、`active.png` 等)。对比归档.zip 里 06-24 旧版 GT:
- **节点数/边数完全一致**(region_0: 193/187,region_100: 126/128)。
- **节点集合完全相同**。
- 仅 pickle 序列化字节不同(dict 遍历序差异),**内容无变化**。

故 `processed/` 里由 `generate_labels.py` 从 `refine_gt_graph.p` 生成的 mask 仍然有效,无需重生成。
