# xian 数据集影像黑边不匹配分析

> 场景:把 sam_road 的 `didi_xian` 数据集接入 P2CNet(像素级道路 mask 补全)做对比基线时,
> 发现部分 region 的卫星影像有黑色边缘,但 GT 道路 mask 与 partial 先验在这些黑边区域仍有道路像素。
> 本文记录该"不匹配"现象的实测数据、根因、规律,以及对训练评测的影响与建议。

---

## 一、现象

肉眼可见:某些 region(如 373)卫星影像 `region_X_sat.png` 的**右侧/下方整片纯黑**,
但同一 region 的 `region_X_gt.png`(GT 道路 mask)和 `region_X_refine_gt_graph_partial.png`
(partial 先验)在黑边区域内**仍有道路像素**。

典型样本 region_373:
- 黑边在**下半部**(从第 142 行到 399 行全是黑),占 64.5%;
- 黑边区 sat 像素值 = **0.00**(真黑,无数据,不是阴影);
- GT 道路有 35.9% 落在黑边内,partial 有 42.8% 落在黑边内。

即 **"img 黑,但 road 的 gt / partial 不黑"**。

---

## 二、根因

**影像覆盖范围 < 路网覆盖范围。** 两个数据源来源不同:

| 数据 | 来源 | 覆盖 |
|---|---|---|
| `region_X_sat.png` | 卫星影像 tile | 受影像实际覆盖范围限制,边缘 tile 会有 no-data 纯黑区 |
| `region_X_gt.png` / partial | 矢量路网(OSM / didi 轨迹渲染) | 路网覆盖范围更大,在影像黑边处仍有路,照画不误 |

像素层面 sat 与 gt/partial **是坐标系对齐的**(同一 400×400 tile),只是 sat 在边缘处没影像数据(像素=0),
而路网在该处有路。两者数据源覆盖范围不一致 → 产生"sat 黑边 vs gt 有路"的不匹配。

> 这是数据集采集/切片的固有特性,**不是错位 bug**。sat 的黑是"无数据"(像素 0),
> 不是阴影(阴影像素 ~10-15,且零散小块;no-data 是整条边缘全 0)。

---

## 三、38 个边缘黑边 region 的精确规律

378 个 region 是从一块大卫星影像按 **18 列 × 21 行** 网格切出的(18×21=378)。
影像实际覆盖区比网格小,导致**最右一列**与**最底一行**的 tile 贴到影像边缘 → 出现 no-data 黑边。

按"右 16 列 100% 黑 / 下 16 行 100% 黑"判定,边缘 region 共 **38 个**(= 右列 21 ∪ 底行 18,交集为 377):

| 批次 | region id | 黑边主轴 | 数量 |
|---|---|---|---|
| **A 批(最右列)** | 17, 35, 53, 71, 89, 107, 125, 143, 161, 179, 197, 215, 233, 251, 269, 287, 305, 323, 341, 359 | **右侧**整条黑(右16列 100%);下边仅右下拐角沾一点(下16行 67%) | 20 |
| **B 批(最底行)** | 360, 361, 362, 363, 364, 365, 366, 367, 368, 369, 370, 371, 372, 373, 374, 375, 376 | **下方**整条黑(下16行 100%);右边仅拐角沾一点(右16列 64%) | 17 |
| **377(右下角)** | 377 | 右 + 下都整条黑(右16列 100%,下16行 100%) | 1 |

### 规律速记
- **A 批 = 最右列**:`id ≡ 17 (mod 18)`,即 17, 35, 53, …, 359(步长 18,共 20 个,21 行里右列)。
- **B 批 = 最底行**:360–377 连号(共 18 个,含 377)。
- **377 = 右下角**:最右列 ∩ 最底行,两边都黑,最严重(右半 100% + 下半 100%)。
- A 批 ∪ B 批 = 38 个(377 在两批交集,只算一次)。

### split 分布

| split | 边缘 region 数 | region id |
|---|---|---|
| train | 29 | 71, 89, 107, 125, 143, 161, 179, 197, 215, 251, 287, 305, 323, 341, 359, 360, 361, 362, 363, 365, 366, 367, 368, 369, 371, 372, 373, 374, 375 |
| val | 4 | 233, 269, 364, 377 |
| test | 5 | 17, 35, 53, 370, 376 |

其中 **GT 完全无道路**的边缘 region 有 5 个(test 的 17/35/53、train 的 215/251)—— 纯空白,训练浪费但不伤模型。

---

## 四、对 P2CNet 训练评测的影响

P2CNet 是双分支(sat 看卫星图 + par 看 partial 路网图)的 mask 补全,黑边对其影响:

| 影响点 | 说明 |
|---|---|
| **SAT 分支输入异常** | 黑边区 sat=0(全黑),SAT 分支无视觉信息,只能靠 partial 分支补。属于 P2CNet "partial 补全"的正常场景,但黑边区无视觉梯度。 |
| **mp_loss 监督失真** | `mp = complete - partial`,黑边区 partial 未覆盖的道路会被监督让 SAT 输出,但 SAT 输入是 0 → 逼 SAT 在无信息处硬预测,产生有害梯度。 |
| **IoU/mIoU 评估失真** | 黑边区 gt 有路,模型若预测全黑 → recall 虚低;若预测全路 → precision 虚低。部分 region 有 35.9% 道路落在黑边,影响不小。 |
| **占比 10%** | 38/378 region 受影响,系统性拉低指标。 |

---

## 五、处理建议

| 方案 | 做法 | 代价 | 推荐度 |
|---|---|---|---|
| **先不管,跑 baseline** | 带着黑边原样训练评测 | 指标含黑边干扰 | ⭐ 推荐先做 —— sam_road 结果也含这些 region,要对比须用同样数据 |
| 过滤 train 的边缘 region | 从 `train.txt` 删掉 train 的 29 个边缘 region | 损失 10% 训练数据;val/test 不动 → 评测仍含黑边,与 sam_road 可比 | 可选(仅提训练效率) |
| 逐 region 裁有效区 | 算每个 region 的有效(非黑)边界,裁掉黑边后 pad 回 400 | 工作量中等;P2CNet 要求固定尺寸 | 可选优化 |
| 黑边 mask 掉 loss/metric | 在黑边区忽略 loss 与 IoU | 要改 trainer loss 与 `MixMetrics` → 改原码 | 不推荐 |

**核心权衡**:sam_road 的基线结果(如 didi_xian APLS 0.6226)是**含这些黑边 region** 测的。
P2CNet 要与之公平对比,就必须用**相同的 region 集合**评测。因此 val/test 的 9 个边缘 region **不能删**,
否则指标不可比。建议先跑 baseline,再决定是否做黑边 mask 优化。

## 六、验证脚本

复现上述统计(在 sam_road 仓库根目录,`samroad` conda 环境下运行):

```python
import cv2, numpy as np, json
base='datasets/didi/xian/2019_400'
split=json.load(open('datasets/didi/xian/data_split.json'))
allids=sorted([int(x) for x in split['train']+split['validation']+split['test']])
def edges(sat):
    black=(sat.max(axis=2)<15); H,W=black.shape
    return black[:,W-16:].sum()/(H*16), black[H-16:,:].sum()/(16*W)  # 右16列黑%, 下16行黑%
edge=[]
for i in allids:
    r,l=edges(cv2.imread(f'{base}/region_{i}_sat.png'))
    if r>0.9 or l>0.9: edge.append(i)   # 右或下整条黑
print('边缘黑边 region:', edge, '共', len(edge))   # 应得 38 个
```

---

## 七、结论

- xian 数据集存在 **38 个(10%)边缘 no-data 黑边 region**,根因是 **18×21 切片网格超出卫星影像覆盖范围**,
  最右列(id≡17 mod 18)右侧黑、最底行(360-377)下方黑、377 右下角双黑。
- 黑边处 sat 无数据(像素 0),但 gt/partial 的路网覆盖更广,**道路照画** → "sat 黑 vs gt 有路"的不匹配。
- 这是数据固有特性,非 bug;对 P2CNet 训练有干扰但可接受;**评测须与 sam_road 同 region 集合**以保证可比,故 val/test 边缘 region 不可删。
- 建议:先跑 baseline,后续视指标再决定是否做黑边 mask 优化。
